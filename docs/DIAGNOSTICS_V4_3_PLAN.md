# V4.3 실행·발송·성능 진단 — Stitch 선행 상세 설계

기준일: 2026-11-03. 기존 V3.1/V4/V4.1/V4.2의 누적 소스 위에 구현한다. 공개 v4.2.0 및 개발 Git HEAD는 유지한다.

## 1. 승인 범위와 디자인 원본

포함: Job 실행 정체·기록 공백·RUNNING 반복·지연 급증, 메시지 단계 및 원 발송/문자 대체 결과, Job별 처리율·단계 지연·시간 버킷·수동 대기량 관측.
제외: 다중 Agent/HA, 설정파일 연계 확장, 버전별 호환성 확장, 모바일, 재발송/운영 명령, 외부 전송, 공개 릴리스.

Google Stitch의 실제 DESKTOP 생성 결과를 먼저 확보한 후 본 설계를 작성했다.
- 프로젝트: `9409874347473150518` (PRIVATE)
- Job 실행 진단: `4c2bc6e418db423188f501520339047b`
- 메시지 결과 추적: `9e95d4ac08e44ebba35b8d846ed2425e`
- 처리 성능·대기량: `023614fb1d954b1b93f9e453ae6d8a0a`

실제 HTML/CSS·PNG 원본과 SHA-256을 별도 인계 디렉터리에 보관한다. 구현은 원본 CSS 토큰, 카드, 가로 탭, 표, 메시지 여정, 근거 패널 구조를 재사용하고 동적 데이터/실제 동작을 연결한다. 원본에 등장하는 가상 수치, `0/1000=성공` 등의 임의 코드 해석은 구현 근거가 아니다. 원본 시안에 대한 의미 보정은 명시적 설계 변경이다. 다크 모드/추가 모달 제안은 이번 범위가 아니다.

## 3. Job 진단 계약

조회 구간은 KST 반개구간 [시작,종료), 최대 31일. 정상 기준은 사용자가 지정하며 동일 Agent/수집 조건 확인이 필요하다. 동일 분석의 겹치는 기준/조사 구간은 거부한다. 비교 구간은 동일 길이로 제한한다.

기준 주기는 파일별 완료 기록의 양의 간격 중앙값으로 산출한다. 최소 4개 간격과 안정성 조건을 충족해야 한다. 파일 경계를 이어 공백을 만들지 않는다. 기준 구간의 파일별 주기가 불일치하면 단일 정상 주기를 확정하지 않는다. 기준이 없으면 조사 구간의 관측 주기임을 구분한다.

관측 공백 기준은 `max(기준 간격×3, 기준 간격+5초)`이다. 공백 내 간격 상당 횟수는 계산상 참고이며 실제 스케줄 실행 누락 횟수가 아니다. 마지막 기록과 수집 시각은 별도 표시하고 그 차이를 장애 발생 시점으로 사용하지 않는다. 주기·입력 수집시각 근거가 충분하면 마지막 완료 이후 후속 완료 미관측을 별도 표시하며 부분 자료의 중단 판정은 보류한다.

RUNNING 기록은 같은 파일·Job 내 가까운 기록을 묶어 반복군과 횟수/구간을 표시한다. 단일 실행의 스레드 정지를 확정하지 않는다. 같은 Agent·Job의 명시 완료 기록이 끼면 다른 로그의 완료라도 반복군을 분리한다. 최소 반복 횟수는 3회 기본값이다.

급증은 유효한 기준 소요시간 표본 5개 이상일 때 `max(기준 P95×3,10초)`와 비교한다. 기준이 부족하면 상대 급증 대신 10초 절대 지연 관측으로 구분한다. 임계값은 화면에서 확인/조정 가능하다. P95 표본이 상한을 넘으면 부분 표본 백분위를 전체 값처럼 제공하지 않는다.

## 4. 메시지 결과 계약

연결 키는 같은 레코드에 명시된 `SERVICE_SEQNO + MESSAGE_SEQNO`. 서비스가 다른 같은 메시지 번호는 분리한다. 원문 ID는 검색 입력과 로컬 스캔에만 쓰며 결과/내보내기에는 세션 HMAC 가명만 남긴다. 시간적 근접성으로 서로 다른 레코드의 ID를 조합하지 않는다.

원 발송 `SEND_RESULT_CODE1`, 문자 대체 `SEND_RESULT_CODE2`는 명시적인 결과 수신 레코드에서만 판정한다. 제공된 통합메시징 운영 매뉴얼의 발송 결과 확인 절은 해당 필드의 `OK`를 성공으로 정의한다. SQL SELECT/UPDATE/INSERT의 코드 리터럴, SEND_FLAG=Y, RESPONSE_CODE=S는 최종 성공 근거가 아니다.

유효한 비OK 결과코드는 실패 관측으로 분류하되 상세 사유는 임의 매핑하지 않는다. 빈 값, NULL/미확인/진행 중 표기, 알려지지 않은 비정형 값은 판단 보류한다. 원 발송 실패와 대체 성공은 별도로 유지하고 전체 표시를 `대체 성공`으로 한다. 원 발송만 실패하고 대체 여부가 불명확하면 전체 실패로 확정하지 않는다. 양쪽 실패 또는 원 발송 실패+명시적인 대체 없음(003)일 때만 최종 실패 관측이다.

동일 키에 상반 결과가 있으면 마지막 값 우선으로 덮지 않고 `충돌·검토 필요`로 분리한다. 재시도/중복은 기록 횟수와 고유 메시지 수를 분리한다. 요청→결과 관측 간격은 유일한 요청 1건/결과 1건이고 시각 순서가 유효한 경우만 계산한다.

여정의 단계 상태는 미관측/표지 관측/명시 완료/명시 실패/혼재를 구분한다. 최종 결과의 실패가 TCP나 DB 이관 실패를 자동 의미하지 않는다. 성공률 분모는 판정 가능한 고유 메시지에만 한정하고 미확인·충돌 및 자료 상한을 함께 표시한다.

## 5. 성능 및 대기량 계약

- 구간 관측 처리율 = 완료 로그의 유효 작업대상 합계 / 조사 구간 초.
- 실행시간 기준 처리율 = 대상과 양의 소요시간이 함께 있는 동일 완료기록의 대상 합계 / 해당 소요시간 합계. 개별 TPS 단순 평균을 사용하지 않는다.
- Job별 평균/P50/P95/최대와 단계별 소요시간/표본 수를 제공한다. 서로 다른 Job의 대상을 고유 메시지 수로 합산하지 않는다.
- 시간 버킷은 1분/5분 선택. 긴 구간은 최대 600버킷으로 폭을 자동 확대하고 실제 폭을 표시한다. 기록이 없는 버킷은 미관측(null), 대상 0이 기록된 버킷만 0이다. 마지막 버킷은 실제 구간 길이로 나눈다.
- 단계 시간은 겹치거나 표본 수가 다를 수 있다. 강제로 100%로 정규화하지 않고 가장 긴 관측 단계/지연 집중 후보로 표시한다. Lock/네트워크 단독 원인 확정 없음.
- 대기량은 담당자 숫자 관측(시각,건수,동일 조건 확인)을 세션 내에서만 보관한다. 최대 200개. 동일 시각의 상반 값은 거부한다. 비교 확인이 없으면 변화율을 계산하지 않는다. 순증감/초이지 실제 처리속도·유입률·해소 ETA가 아니다.

## 6. 데이터·개인정보·이전 분석 호환

기존 manifest/events.jsonl/analysis_result 및 문의·사례 스키마를 수정하지 않는다. 새로운 강제 마이그레이션 없음. 원본이 존재하는 기존 분석에도 온디맨드 메시지 조회를 적용한다. 기존 분석을 자동 재분석하거나 삭제하지 않는다.

표시/다운로드는 허용된 구조적 필드만 사용한다. 고객사명·Redmine URL·원본 경로·본문·SQL·인증정보를 신규 요약에 포함하지 않는다. 원본 근거 열기는 서버가 제공한 참조 집합의 인덱스만 수용하며 경로/줄번호를 브라우저 입력으로 임의 구성하지 못한다. HTML에는 모든 동적 문자열을 escape/textContent로 넣는다.

원본 조회는 기존 SHA-256/경로/인코딩/레코드 크기 검사를 재사용한다. 입력/이벤트 변경 시 세션 캐시를 무효화한다. 외부 CDN·폰트·이미지를 UI 런타임에서 요청하지 않는다. 고객사 데이터는 Stitch로 전달하지 않으며 생성 프롬프트는 가상 예시만 사용했다.

## 7. 독립 검증 가능한 구현 묶음

1. 디자인 원본 확보 및 설계/수용 기준 확정 (Stitch 3화면, 원본 해시, 의미 보정).
2. Job 진단 + 성능 집계 (경계/결측/부분자료/샘플 제한/분모 검증).
3. 메시지 결과/단계 추적 (수락≠성공, 원발송/대체, 중복/충돌/위조본문/SQL/원본 변경).
4. Stitch 기반 웹 UI와 기존 분석기 연결 (실제 필터/행 선택/근거/요약/대기량 입력).
5. 전체 회귀/합성 UI/대용량/보존 검증 및 인계. 공개 배포 별도 승인.

## 8. 수용 테스트

기존 229개 테스트를 유지한다. 신규 단위 테스트는 위 수식 및 부정 사례를 함께 검증한다. 합성 로그로 정상/공백/RUNNING/급증, 원발송 성공/실패, 대체 성공/실패, 수락만 관측, 상반 결과, 메시지 ID 결측/서비스 분리, SQL·본문 내부 위조, 해시 변경, 빈 구간/시간대/자정, 과대 레코드와 표시 상한을 검증한다.

UI는 기존 Streamlit 진입 및 세 화면 전환, 필터/검색/페이지/근거/요약/수동 관측이 실제 데이터에 연결되는지 확인한다. 1280/1440/1920px 데스크톱을 대상으로 한다. Mac 검증과 Windows 현장 검증을 구별한다. 독립 브라우저 도구의 429는 기록하고, 가능하면 별도 격리된 로컬 Playwright로 검증한다.
