# V4.3 실행·발송·성능 진단 사용 안내

> **V4.3.1 입력 보정:** 파일을 등록했지만 진단값이 없는 경우 [입력 복구 안내](DIAGNOSTICS_V4_3_1_FIX.md)를 확인하세요. 조회 구간 설정만으로 날짜 없는 기록에 날짜가 생기지 않으며, 원본 재해석은 세션 한정으로 기존 분석을 보존합니다.

V4.3은 로컬 개발본입니다. 공개 v4.2.0을 덮어쓰거나 자동 업데이트하지 않습니다. 기존 분석·문의·해결 사례는 유지하며 강제 마이그레이션이나 자동 재분석을 하지 않습니다.

## 시작 위치

기존 분석을 선택한 뒤 **분석 대시보드 → 실행·발송·성능**으로 이동합니다. 새 화면 내부에 Job 실행 진단 / 메시지 결과 추적 / 처리 성능·대기량의 세 탭이 있습니다. Google Stitch에서 실제 생성한 데스크톱 화면을 기반으로 만들었으며 별도의 모바일 화면은 없습니다.

기존 Windows 실행 진입점은 START_WINDOWS.bat입니다. 이번 작업으로 사용자 Windows 설치가 갱신된 것은 아닙니다. 현재 개발본의 실행은 기존 Python 3.13 가상환경을 사용하며 추가 필수 Python 패키지는 없습니다. 새 diagnostics_web 디렉터리의 HTML/CSS/JavaScript도 함께 있어야 합니다.

## 1. 조사 조건과 정상 기준

`조사 조건` 버튼을 누르면 상단의 입력 영역이 열립니다. 시작 포함·종료 미포함의 KST 구간을 지정하고 `진단 조건 적용`을 누릅니다. 기본 구간은 제공 자료의 인식된 시각으로 정하며 날짜 근거가 없으면 직접 입력합니다. 오늘 날짜를 임의로 넣지 않습니다.

정상 구간과 비교할 때는 기준 분석·기준 시작/종료를 지정하고 동일 Agent/수집 조건 확인에 체크합니다. 두 구간은 같은 길이여야 하며 같은 분석에서 겹치는 구간은 거부합니다. 기준 구간을 사용자가 정상으로 지정하는 것이지 프로그램이 정상임을 인증하는 것은 아닙니다.

기본 기준은 P95 배율 3배, 절대 지연 하한 10초, RUNNING 반복 3회입니다. 화면에서 변경 가능합니다. 정상 소요시간 표본이 5개 미만이거나 백분위가 제한되면 상대 급증 대신 절대 지연으로 표시합니다.

## 2. Job 실행 진단

KPI는 실행 기록 수, 관측 공백, RUNNING 건너뜀, 급증/절대 지연 기록입니다. 표에서 Job을 선택하면 선택 Job의 소요시간 차트와 근거가 바뀝니다. Job 필터와 표 페이지를 사용할 수 있습니다.

주기는 파일별 완료 기록에서 충분하고 안정적인 간격이 있을 때만 사용합니다. 파일 경계를 이어서 가상의 공백을 만들지 않습니다. RUNNING 반복군 사이에 같은 Agent·같은 Job의 명시 완료가 있으면 다른 로그의 완료 기록도 사용해 반복군을 분리합니다.

입력된 실제 수집시각이 있고 정상/관측 주기 근거가 충분하면 `마지막 완료 이후 후속 완료 미관측`도 표시합니다. 부분 자료는 판정을 보류합니다. 이 시각은 실제 Agent 종료나 장애 시작 시각이 아닙니다. PID·스레드·DB·네트워크 근거와 함께 확인하세요.

근거 버튼은 기존 원본 SHA-256 검증과 마스킹 뷰에 연결됩니다. 로컬 화면은 V4.1 원본명 연결이 있으면 그 이름을 표시하고, 이름이 없으면 별칭과 `원본명 미보관`을 표시합니다. 원본명을 새로 추측하지 않습니다.

## 3. 메시지 결과 추적

이 탭은 자동으로 원본을 읽지 않습니다. `원본 조회 조건`에서 필요하면 SERVICE_SEQNO/MESSAGE_SEQNO를 입력하고 로컬 원본 조회에 동의한 뒤 `메시지 결과 조회`를 실행합니다. 두 식별값이 같은 레코드에 명시된 자료만 연결합니다. 서로 다른 서비스의 같은 메시지 번호는 분리됩니다.

일반 화면·요약에는 원문 식별값 대신 세션별 가명을 사용합니다. 화면의 가명 검색과 원문 번호 검색은 다른 기능입니다. 상태 필터, 25건 페이지, 메시지 선택 후 단계·원 발송/문자 대체 결과·근거를 확인할 수 있습니다.

| 표시 | 필요한 관측 |
|---|---|
| 원 발송 성공 | 명시적인 결과 수신 기록의 SEND_RESULT_CODE1=OK |
| 문자 대체 성공 | 명시적인 결과 수신 기록의 SEND_RESULT_CODE2=OK |
| 최종 실패 관측 | 원 발송/문자 대체 모두 실패, 또는 원 발송 실패와 명시적 대체 없음(003) |
| 원 발송 실패·대체 미확인 | 원 발송 실패는 관측되지만 대체 결과/정책이 불충분 |
| 요청 수락·결과 미확인 | RESPONSE_CODE=S 등 요청 수락만 관측 |
| 결과 충돌·검토 필요 | 같은 메시지에 상반/상이한 결과, 상충하는 대체 정책 등 |
| 결과 미확인 | 결과수신 근거가 없거나 의미가 불명확한 값 |

CODE1/2의 OK 성공 의미는 제공된 통합메시징 설치운영 매뉴얼의 발송 결과 확인 절을 기준으로 합니다. 숫자 0000/0/1000을 모든 필드의 보편적 성공 코드로 간주하지 않습니다. 유효 비OK 코드의 상세 사유는 별도 코드 명세 확인이 필요합니다.

DB 선점 → 파일 생성 → TCP 전송 → 요청 수락 → 결과 수신 → DB 이관은 `표지 관측 / 명시 완료 / 명시 실패 / 혼재 / 미관측`으로 구분합니다. 빠진 단계는 실패가 아닙니다. 메시지 최종 실패가 TCP 전송 실패를 자동 뜻하지 않습니다.

SQL의 WHERE/INSERT/UPDATE 값, SEND_FLAG=Y, 본문에 섞인 가짜 필드, ID가 불명확한 바인드는 결과로 판정하지 않습니다. 결과 수신 문맥이 없으면 코드가 보여도 최종 결과로 쓰지 않습니다. 원문 문법이 지원 범위를 벗어나면 추가 로그가 필요합니다.

요청→결과 관측 간격은 유일한 요청 1건과 결과 1건만 있을 때 계산합니다. 재시도·중복·상반 결과를 임의로 짝짓지 않습니다. 성공률은 판정 가능한 고유 메시지만 분모로 사용하며 미확인/충돌을 제외합니다. 이는 전체 업무 발송 성공률이나 수신자의 열람률이 아닙니다.

## 4. 처리 성능·대기량

상단 수치는 선택 Job 기준입니다. 다른 Job의 작업대상을 합산해 고유 메시지 처리량처럼 표시하지 않습니다.

- 구간 관측 처리율: 완료 로그의 유효 작업대상 합계 / 전체 조사 구간 초.
- 실행시간 기준 처리율: 대상과 양의 소요시간이 함께 있는 동일 완료기록의 대상 합계 / 그 소요시간 합계.
- 평균·P50·P95·최대, 기준 P95 대비 배율, 단계별 평균과 표본 수를 별도로 표시합니다.

기록이 없는 시간 버킷은 미관측이며, 실제 대상 0이 기록된 경우만 0입니다. 긴 구간은 600버킷 이하로 폭을 늘리고 실제 집계 폭을 표시합니다. 단계 시간은 중첩될 수 있으므로 100% 합계나 단일 병목 원인으로 해석하지 않습니다.

대기량은 로그에서 추정하지 않습니다. 담당자가 DB 등에서 확인한 시각·대기 건수를 직접 입력합니다. 동일 서비스/조회 조건 확인에 체크한 관측만 순증감을 비교합니다. 순증감/초는 처리속도나 유입률이 아니며 해소 ETA는 산출하지 않습니다.

**대기량 입력은 현재 Streamlit 세션에만 보관됩니다.** 앱/브라우저 세션을 종료하거나 새로고침하기 전에 필요한 비식별 JSON 요약을 저장하세요. 영구 저장·문의 자동 반영·DB 자동 조회는 이번 기능에 포함되지 않습니다.

## 5. 보존·보안·표시 제한

고객 로그, workspace, knowledge, 문의 저장 계약은 변경하지 않습니다. 기존 manifest/events.jsonl/analysis_result 스키마도 유지합니다. 원본 조회/근거 열기는 해시를 검증하며 원본 변경이 확인되면 거부합니다.

CSV 대신 이 화면의 비식별 JSON 요약을 제공합니다. 원본 경로·고객사명·Redmine URL·메시지 본문·SQL·원문 메시지 ID를 포함하지 않습니다. 로컬 원본명과 내보내기 자료는 별도 전달 경로를 사용합니다. 외부 CDN/폰트/API를 요청하지 않으며 운영 명령/재발송/DB/Redmine 쓰기 기능이 없습니다.

순서 분석은 전체 100,000개, 파일·Job별 50,000개까지입니다. 상한에 걸린 시퀀스는 공백/반복군 판정을 보류합니다. 분포 표본은 기존 50,000개/전체 250,000개 상한을 따르며, 넘으면 백분위를 빈 값으로 남깁니다. 메시지는 5,000개, 이벤트 상세 20,000개, 메시지별 대표 근거 50개(전체 20,000개) 제한입니다. 집계/상세 생략/식별값 제외를 구분해 표시합니다. 구간 또는 메시지 검색 조건을 좁혀 사용하세요.

## 6. 검증 범위

합성 단위·회귀 테스트, Streamlit AppTest와 격리 Chromium에서 실제 컴포넌트/서버 연결·데스크톱 레이아웃을 검증합니다. Windows 네이티브, 실제 고객사 원본, NAS·기업 ACL/백신, 모든 고객사 커스텀 로그의 호환성은 별도 검증 대상입니다. 상세 합성 테스트 기록과 브라우저 캡처·내부 검증 인계 자료는 공개 저장소에 포함하지 않고 별도 보관합니다.
