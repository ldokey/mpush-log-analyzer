# V4.1 — 고객 문의 중심 로그 조사·해결 기록

## 1. 적용 내용

기존 V3.1/V4 분석 엔진·대시보드를 유지하고, 문의 번호를 중심으로 파일·분석·해결 기록을 연결한다.

상단 메뉴는 **문의·해결 기록 / 분석 대시보드 / 자료 가져오기 / 사례 라이브러리 / 내보내기·관리**로 구성된다. 분석 대시보드의 V4 여섯 세부 화면은 그대로 유지한다.

### 로컬 원본명과 외부 전달 자료 분리

새로 가져온 파일은 원본명과 고객사 문의 루트 기준 상대경로를 별도 로컬 관리 파일에 보존한다. 압축 내부라면 `#12345_고객사/logs.zip!/A1/debug_2026-11-02.log [file_01]`처럼 표시한다. 이는 형식 예시이지 실제 고객사 로그가 아니다.

원본 파일은 기존처럼 익명 저장명으로 격리하고 `file_id`와 SHA-256을 유지한다. 일반 CSV·AI 자료·고객 전달용 비식별 보고서는 익명 별칭을 사용한다. 고객사명·원본 경로·Redmine URL·담당자 자유 메모를 자동으로 외부 자료에 넣지 않는다.

V4 이전 분석은 원본명 자체를 저장하지 않았으므로 이름을 추측하지 않는다. **내보내기·관리 → 기존 분석 원본 파일명 복구**에서 동일한 내용의 원본 로그를 다시 선택하면 해시를 대조해 이름만 연결한다. 원본이 없으면 기존 별칭을 표시한다. 기존 분석을 새 문의에 연결하는 기능도 제공한다.

## 2. Windows에서 최초 설정

프로그램과 분석 저장소는 개인 로컬 디스크에서 실행하는 구성을 권장한다. 고객사 원본을 모아 둔 네트워크 드라이브는 읽기용 자료 폴더로 등록한다. 이 버전은 별도의 원격 서버에서 사용자 PC의 Z: 드라이브를 읽는 기능이 아니다. **앱이 실제로 실행되는 Windows 계정**에서 해당 드라이브에 접근할 수 있어야 한다.

1. 자료 가져오기에서 **고객사 문의 폴더·Redmine 연결 설정**을 연다.
2. 고객사 문의 폴더들이 바로 아래에 있는 루트 절대경로를 입력한다. 예: `Z:\...\고객사 문의 파일`.
3. **Redmine 기본 주소**에 조직의 주소를 입력한다. `/issues/번호` 이전까지 입력한다.
4. 연결 설정 저장을 누른다. 설정은 이 프로그램의 로컬 `workspace/import_settings.private.json`에 저장된다.

번호만 입력한 문의와 링크로 입력한 문의를 같은 것으로 연결하려면 기본 주소를 먼저 설정해야 한다. 서로 다른 Redmine 서버의 같은 번호는 별개 문의다. 서버를 지정하지 않고 만든 문의와 나중에 서버를 지정한 문의를 자동 합치지 않는다.

## 3. 평소 사용 흐름

1. 받은 자료를 기존 방식대로 `#번호_고객사` 폴더에 옮긴다.
2. 자료 가져오기에서 **등록 폴더에서 선택 → 문의 폴더 목록 새로고침**을 누른다.
3. 번호/고객사로 검색하고 문의 폴더를 선택한다.
4. **이 문의의 로그·압축 목록 확인**을 누른다. 선택한 문의 폴더만 탐색한다. 다른 문의 폴더의 로그 내용은 읽지 않는다.
5. 원본 경로·압축 내부 경로·파일 크기·제외 이유를 확인한다. A1/A2나 서버가 다르면 별도 분석으로 나눈다. 경로 기준 자료 묶음은 Agent 식별을 보증하지 않는다.
6. 같은 Agent의 파일을 골라 **선택 파일 읽기·분류**를 누른다. 폴더명에서 문의 번호·고객사 후보를 채우며, 직접 수정할 수 있다.
7. Agent 구분, 버전, 기준 날짜, 수집시각, 파일별 완전성·로그 종류를 확인한 후 **문의에 연결하고 분석**을 누른다.
8. 분석 대시보드에서 원본명·근거 줄·개별 이벤트를 조사하고 문의·해결 기록에서 내용을 정리한다.

폴더를 등록해도 상시 감시하거나 자동으로 모든 파일을 분석하지 않는다. 새 자료를 옮긴 뒤 새로고침한다. 같은 문의·Agent·내용·날짜·분석 조건이면 기존 분석을 재사용하고, 추가 자료나 조건이 달라지면 새 분석으로 연결한다. 기존 문의의 자유 메모는 가져오기 작업으로 덮어쓰지 않는다.

## 4. 문의·해결 기록

문의 번호/링크, 고객사, 제목, 상태, 문의 증상, 로그에서 확인한 사실, 원인 후보·확인된 원인, 실제 조치, 검증 결과, 다음 확인사항을 저장한다.

상태는 접수 / 분석 중 / 추가자료 대기 / 조치 적용 / 해결 확인 / 보류다. **해결 확인은 실제 조치와 검증 결과가 있어야 저장된다.** 이는 로컬 관리 상태이며 Redmine 서버의 상태를 자동으로 바꾸지 않는다. 한 문의에 여러 Agent 또는 추가 수집분의 분석을 연결할 수 있다.

동시 편집은 수정 버전으로 검증한다. 다른 화면에서 먼저 변경된 내용을 오래된 화면이 덮어쓰지 못한다. 변경 이력에는 수정 버전·시각·변경 항목을 최근 200회까지 기록한다. 문서 전체의 과거 내용 복원 기능은 아니다.

내부 답변용 TXT는 고객사 메모가 포함될 수 있어 확인 체크 후에만 생성한다. 외부 AI용 비식별 자료와 구분해야 한다. Redmine 링크는 사용자 클릭으로 열며, 앱은 API 키·로그인을 저장하거나 문의를 자동 조회·수정하지 않는다.

## 5. 재사용할 해결 사례

문의 상세의 **재사용할 해결 사례 작성**에서 개인정보·고객 식별정보를 뺀 제목, 증상, 원인, 조치, 검증, 점검 항목과 신호를 직접 정리한다. 내부 메모를 자동 복사하지 않는다.

등록하면 사례 라이브러리의 **검토 대기**로 들어간다. 기존 승인 절차에서 사람이 검토해야 자동 매칭에 사용된다. 검토 승인과 원인·해결 검증은 별도다. Redmine 이슈 번호와 로컬 문의 식별자는 사례 출처로 연결하지만 내부 서버 URL은 사례에 자동 포함하지 않는다. 같은 내용의 사례를 반복 등록하면 기존 연결을 재사용한다.

## 6. 파일 형식과 한계

- 일반 `.log`, `.txt`, `.ini` 및 회전 로그 `.log.1`, `.log.2026-11-02`를 지원한다.
- 파일명의 `YYYYMMDD`, `YYYY-MM-DD`, `YYYY_MM_DD` 날짜를 인식한다. 폴더 수정일을 발생일로 추정하지 않는다.
- ZIP / TAR / TAR.GZ / TGZ / 단일 GZ를 읽는다. 선택한 내부 파일을 메모리에서 제한적으로 읽으며 원본 위치에 압축을 풀지 않는다.
- 암호화 ZIP, 링크·특수파일, 경로 탈출, 비정상 압축률, 수량·용량 초과는 거부한다. 중첩 압축, RAR/7z는 자동 해제하지 않고 제외 이유를 표시한다.
- 파일당 350MiB, 선택한 해제 내용 합계 600MiB, 한 분석 30개를 유지한다. 압축 항목 2,000개, 폴더 검색 항목 5,000개, 깊이 12단계의 제한을 둔다. TAR 메타데이터·패딩까지 읽기 한도를 적용한다.
- 파일을 스캔한 뒤 복사·수정되었으면 다시 스캔하도록 거부한다. 운영 중 계속 기록되는 파일이 아니라 전달받은 복사 완료 자료를 사용한다.
- 동일 내용이어도 파일명 기준 날짜가 다르면 별개 관측 자료로 유지한다. 같은 날짜·동일 내용의 중복 입력은 최초 파일을 유지한다. 부분적으로 겹치는 로그 구간까지 자동 병합하는 기능은 아니다.

## 7. 보관·업데이트

문의는 `workspace/support/issue_*.json`, 원본명 연결은 각 분석의 `local_context.private.json`에 저장한다. 원본명과 문의 메모는 로컬 비공개 운영 데이터다. 암호화 저장을 제공하지 않으므로 Windows 계정과 NTFS ACL을 적절히 관리해야 한다.

프로그램 폴더를 새로 만들 때 기존 `workspace/`와 `knowledge/inbox/`, `knowledge/approved/`를 버리지 말고 별도 백업한다. 이 변경은 별도 패키지 설치를 필요로 하지 않는다. 기존 설치 폴더의 코드를 업데이트하면 기존 `.venv`를 유지할 수 있다. 여러 버전이 공유하는 가상환경 구조 자체를 도입한 것은 아니다.

## 8. 검증 범위

실제 고객사 로그 원문은 제공되지 않았다. 첨부된 폴더 화면, 기존 코드, 합성 로그·합성 압축으로 개발했다. Mac에서 단위/회귀·Streamlit 화면 조작을 검증했으며, 사용자 Windows/NAS 권한, 실제 고객사 파일 형식, 비표준 한글 ZIP 파일명 인코딩, 실제 대용량 압축 성능은 별도 확인 대상이다.

원인 확정, 실제 메시지 수신 성공 판정, 자동 Redmine 쓰기, 자동 Agent 조치, 실제 고객 데이터의 외부 전송은 추가하지 않았다.
