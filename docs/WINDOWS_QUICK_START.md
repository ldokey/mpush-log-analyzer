# Windows 실행 안내 — MPushAgent Log Analyzer

이 문서는 **Windows 10/11 64비트**에서 MPushAgent Log Analyzer를 로컬 웹 프로그램으로 실행하는 방법입니다.

> **실행 파일:** 프로젝트 최상위 폴더의 `START_WINDOWS.bat`를 더블클릭합니다. 이 파일은 **독립 EXE가 아닌 실행용 BAT**입니다. Windows에 Python 3.13(64비트)이 미리 설치돼 있어야 합니다. 초기 실행 시 필요한 Python 패키지를 설치하기 위해 인터넷 연결이 필요할 수 있습니다.

## 1. 준비

1. **Python 3.13 (64-bit)** 설치: [Python 공식 다운로드 페이지](https://www.python.org/downloads/windows/)에서 3.13 x64 설치 파일을 사용합니다. Python Launcher가 있으면 함께 설치합니다. `py`가 없을 경우 `python` 명령으로도 3.13 x64를 찾을 수 있습니다.
2. 프로젝트 **전체 폴더**를 Windows PC의 개인 로컬 디스크(예: `C:\Users\Username\Documents\mpush-log-analyzer`)에 압축 해제합니다. 네트워크 드라이브·NAS·공용 폴더·공유 동기화 폴더는 피하세요.
3. 프로젝트 폴더에 `app.py`, `requirements.txt`, `START_WINDOWS.bat`, `scripts\run_windows.bat`가 모두 있는지 확인합니다. BAT 파일 하나만 내려받아서는 실행할 수 없습니다.
4. macOS에서 생성된 `.venv`를 Windows에 복사하지 마세요. 다른 운영체제/버전의 `.venv`를 자동으로 삭제하지 않습니다.

PowerShell 또는 CMD에서 Python 버전을 확인할 수 있습니다.

```powershell
py -3.13 --version
# py 명령이 없다면 아래를 확인
python --version
```

## 2. 첫 실행과 일반 실행

1. 폴더의 **`START_WINDOWS.bat`를 더블클릭**합니다.
2. 처음 실행하는 경우 `scripts\run_windows.bat`가 Python 3.13(64비트)을 찾아 같은 폴더에 `.venv`를 생성하고, 필요한 라이브러리가 없다면 `requirements.txt`로 설치합니다.
3. 터미널에 `Browser URL: http://127.0.0.1:8501`이 표시되면 해당 PC의 브라우저에서 **http://127.0.0.1:8501** 주소를 엽니다.
4. 분석 종료 시 **실행 창에서 `Ctrl+C`**로 서버를 중단합니다. 웹 브라우저 탭만 닫아서는 프로그램이 종료되지 않을 수 있습니다.
5. 다음 실행부터는 같은 BAT 파일을 더블클릭하면 됩니다. 환경과 패키지가 이미 준비되어 있으면 재설치하지 않습니다.

**대체 실행:** 명령 프롬프트에서 프로젝트 경로로 이동한 다음 `scripts\run_windows.bat`를 직접 실행할 수도 있습니다.

**대용량 로그:** `dbwrap.log`는 파일당 350MiB, 한 번에 올리는 로그는 합계 600MiB까지 허용합니다. 다른 로그 및 `agent.ini`를 함께 올릴 때도 이 제한이 적용됩니다. 300MB급 업로드는 브라우저/Streamlit 메모리와 원본·분석 중간파일을 위한 여유 디스크 공간을 확보한 뒤 시도하세요. 기존에 설치된 Python 라이브러리는 정상적으로 불러올 수 있으면 다시 설치하지 않습니다. 대용량 작업이 느려지거나 메모리 부족이 발생하면 실행 중인 다른 메모리 집약 프로그램을 종료하거나 시간대별 로그를 나눠 분석하세요.

## 3. 로그 분석 방법

1. `로그 업로드` 탭에 Agent 3.2/3.3의 `.log`, `.txt`, `agent.ini` 파일을 업로드합니다. 파일 종류가 자동 분류되지 않으면 직접 선택합니다.
2. 로그 **완전성(전체/일부/미확인)**, 기준 날짜, **실제 로그 수집 시각**을 입력합니다.
3. 분석을 실행해 Job/DB/통신/헬스체크 이상 신호와 근거 시각·파일·줄번호를 확인합니다.
4. `이상 징후·근거`에서 탐지 기준과 측정값을 검토하고, 필요하면 `보고서·관리`에서 보고서나 AI 전달용 비식별 자료를 생성합니다.
5. 외부 AI·고객사에 자료를 전달하기 전, 담당자가 개인정보와 업무상 비밀이 없는지 직접 점검해야 합니다.

## 4. 자주 발생하는 문제

| 현상 | 확인 및 해결 방법 |
| --- | --- |
| `Python 3.13 64-bit was not found` | Python 3.13 **x64**를 설치하고 `py -3.13 --version` 또는 `python --version`으로 확인합니다. 사내 정책상 설치가 금지된 PC라면 IT 관리자에게 문의합니다. |
| `Existing .venv is not Python 3.13` | 기존 `.venv`의 소유자·사용 여부를 확인한 뒤 해당 폴더를 **별도 위치로 이동/백업**합니다. 스크립트는 폴더를 자동 삭제하지 않습니다. |
| 라이브러리 설치 중 오류 또는 `pip` 실패 | 첫 설치 시 PyPI 연결/회사 프록시 정책을 확인합니다. 고객 로그는 외부로 전송하지 않지만, 패키지 설치에는 인터넷 연결이 필요할 수 있습니다. |
| `app.py or requirements.txt is missing` | BAT 파일만 복사하지 말고 원본 프로젝트 폴더 전체를 다시 압축 해제합니다. |
| `8501` 포트를 사용 중이라는 메시지 | 다른 Streamlit 프로세스가 구동 중인지 확인한 뒤 본인이 실행한 프로그램을 정상 종료합니다. 알 수 없는 프로세스를 임의 종료하지 마세요. |
| 브라우저에서 페이지가 열리지 않음 | BAT 창의 오류 내용을 확인하고, **동일한 PC**에서 `http://127.0.0.1:8501`로 접속했는지 확인합니다. |
| 폴더 접근 거부·백신 경고 | 조직 정책과 NTFS ACL을 확인합니다. 보안 소프트웨어를 비활성화하거나 보호 예외를 무단으로 추가하지 마세요. |

## 5. 보안 및 적용 범위

- 앱 웹서버는 `127.0.0.1:8501`에만 바인딩합니다. 외부에 서비스를 공개하거나 MPushAgent Java 프로세스·고객사 DB에 연결하지 않습니다.
- 고객 로그와 `agent.ini` 원본은 프로젝트의 **로컬 `workspace/`** 아래에 저장됩니다. Windows에서 파일 접근 권한은 **NTFS ACL**을 따르므로, 개인 사용자 전용 로컬 디렉터리를 사용하세요.
- Python 패키지 설치는 인터넷에 연결될 수 있지만, 고객 로그를 외부 AI로 자동 전송하는 기능은 없습니다.
- 분석 결과는 원인 **확정**이 아닌 조사용 이상 신호입니다. 로그 공백만으로 프로세스 정지나 네트워크 장애를 단정할 수 없습니다.
- BAT의 문법과 Python 호출 경로는 macOS에서 코드 검토 및 정적 검사를 수행했습니다. **실제 Windows 10/11 실행과 NTFS 권한·기업 백신 환경의 검증은 별도로 필요합니다.**
