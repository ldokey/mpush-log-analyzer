# MPushAgent Log Analyzer — 운영 및 사용 설명서 (MVP 1.0)

## 1. 목적과 실행 환경

MPushAgent 3.2/3.3의 개별 로그 파일을 로컬 Mac에서 분석합니다.
기존 Java Agent, 고객사 DB, CNS 서버에는 연결하지 않습니다.
웹 프로그램은 macOS의 127.0.0.1에서만 실행됩니다.

사용 장비: Python 3.13 이상의 로컬 Mac. 검증 장비는 macOS arm64 / Python 3.13입니다.

    cd /path/to/mpush-log-analyzer
    python3.13 -m venv .venv
    .venv/bin/python -m pip install -r requirements-dev.txt
    bash scripts/run_local.sh

로컬 Mac 브라우저에서 http://127.0.0.1:8501 로 접속합니다.
다른 PC에서 직접 접속할 수 있도록 0.0.0.0 바인딩하거나 인터넷으로 공개하지 마세요.
다른 기기에서 사용해야 한다면 조직의 승인된 원격 접속 방식을 별도로 마련해야 합니다.
작업 종료 시 터미널에서 Ctrl+C를 누릅니다.

## 2. 로그 업로드

'로그 업로드' 탭에서 debug.log, info.log, job.log, dbwrap.log, err.log,
agent.ini(.log/.txt/.ini 확장자) 중 여러 파일을 선택합니다.

- ZIP 미지원. 여러 개별 텍스트 파일을 동시에 선택합니다.
- 1회 분석 = 1개 Agent 인스턴스. A1/A2 또는 다른 서버의 로그는 분리합니다.
- 파일별 원본 전체/일부 추출/확인 불가를 실제 자료 상태에 맞게 표시합니다.
- 기준 날짜와 실제 로그 수집 시각은 별도로 입력합니다.
- 여러 회전 파일은 중복 여부 확인 후 필요하면 종류를 수동 지정합니다.
- 한도: 파일당 50MiB, 최대 30개, 전체 200MiB.
- agent.ini 원본에는 DB 비밀번호·키 등이 있을 수 있으므로 로컬 보관에 주의합니다.

'로컬 분석 작업 생성 및 이상 탐지' 버튼을 누르면:
원본 비공개 저장 → 5종 로그 파싱 → 규칙 기반 이상 탐지 → 승인 사례 매칭 → 비식별 보고서 생성 순서로 실행됩니다.

## 3. 분석 대시보드

- 핵심 지표: 추출 이벤트, Job 실행, 작업대상건수, DB 실행, 이상 징후
- Job별 평균/P50/P95/최대 처리시간 및 DB 유형별 처리시간
- CNS 요청 응답 통계. RESPONSE_CODE=S는 발송 요청 수락이며 최종 수신 성공이 아닙니다.
- 이상 징후를 선택하면 근거 파일 ID와 로그 줄번호를 확인합니다.
- 관련 시각 전후 로그를 함께 보여주지만 원인과 결과로 단정하지 않습니다.
- 시간 범위·로그 종류·Job·원본 파일 필터와 100개 단위 이벤트 페이지를 제공합니다.
- 원본 근거 미리보기에는 구조적 로그 표현만 표시합니다. SQL·메시지·개인정보는 표시하지 않습니다.


### V3: 이상 징후를 확인하는 권장 순서

1. **이상 징후·근거** 탭에서 `근거 시각순` 정렬을 확인하고 발송/DB/통신/헬스체크 유형을 좁힙니다.
2. 표에서 한 행을 선택합니다. 시간은 기록된 근거 또는 Job 실행 구간이며 전체 장애 기간을 뜻하지 않습니다.
3. 탐지된 최대 처리시간, 실제 판정 기준, 정상 표본 등의 수치와 근거 파일 별칭/줄번호를 확인합니다.
4. 아래 마스킹된 근거와 같은 시간대의 관련 로그를 함께 확인합니다. 시간상 인접하다는 이유만으로 원인을 확정하지 않습니다.
5. `이 징후를 AI에 전달하기`에서 Markdown/JSON을 생성·복사합니다. 전체 자료가 필요하면 `보고서·관리` 탭에서 만듭니다.
6. AI에 전달하기 전에 소속 조직의 개인정보·업무 보안 정책에 따라 내용을 직접 확인합니다.

`첫 탐지 근거 시각`, `마지막 탐지 근거 시각`, `수집 시각`은 서로 다른 기준입니다. 수집 시각은 사용자가 입력한 값이며 Agent 로그에 기록된 실행 사실이 아닙니다.

## 4. 해결 사례 라이브러리

별도 AI에게 docs/CASE_AUTHOR_GUIDE.md 및 knowledge/schema/case.schema.json,
knowledge/schema/signal_catalog.json을 전달하여 사례당 JSON 파일 하나를 작성하게 합니다.
고객사 개인정보나 원본 로그 전체는 별도 AI에게 전달하지 않습니다.

'해결 사례' 탭에서 JSON 형식·민감정보 검사 → 검토 대기함 등록
→ 담당자 내용·출처 확인 및 명시적 승인 → 유사 사례 검색에 반영합니다.

AI 초안은 자동 승인되지 않습니다.
원인·실제 조치·해결 검증 근거가 확인된 경우에만 해결 검증 사례로 승인합니다.
그 외에는 참고 사례입니다. 매칭 점수는 검색 우선순위이며 동일 원인일 확률이 아닙니다.
새로 승인한 사례를 반영할 때는 '보고서·관리' 탭에서 기존 분석을 다시 실행합니다.

## 5. 보고서 다운로드

'보고서·관리'에서 분석 작업을 선택한 뒤 Markdown, 인쇄용 HTML, JSON 파일을 받습니다.
보고서에는 원본 SQL, 전화번호, 서버 주소, 고객 메시지, 비밀번호·키가 포함되지 않습니다.
고객사로 전달하기 전 사실관계와 내부 보안 정책을 담당자가 최종 검토해야 합니다.

보고서의 '확인된 이상 징후'는 관측된 로그와 비교 규칙에 따른 신호입니다.
실제 프로세스 종료, 통신 장애, Lock, Agent 결함 등 원인은 별도 근거로 확인해야 합니다.
오류 로그가 없다는 이유만으로 정상 동작을 확정하지 않습니다.

## 6. 로컬 저장·보관·삭제

저장 경로 구조:

    workspace/analysis_<UUID>/
      raw/                    # 원본 로그 및 agent.ini (로컬 전용)
      manifest.json
      events.jsonl
      analysis_result.json
      case_matches.json
      report.md
      report.html
      report.json

파일은 접근 제한된 로컬 경로(디렉터리 0700, 파일 0600)에 보관합니다.
workspace 및 knowledge/inbox, knowledge/approved는 .gitignore 대상입니다.
고객사 원본 자료를 Git에 추가하지 마세요. 외부 AI API 전송은 지원하지 않습니다.

자동 삭제나 자동 보관 기간은 설정하지 않았습니다.
분석 자료를 삭제하려면 '보고서·관리'의 해당 분석 ID를 정확히 입력하고 영구 삭제를 실행합니다.
해당 분석 작업의 원본·결과만 삭제되며 승인된 해결 사례 라이브러리는 삭제하지 않습니다.
예상하지 않은 파일이 있으면 안전을 위해 UI 삭제를 거부합니다.

고객사 자료 보관 기간과 접근 권한은 소속 조직의 정보보호 규정을 우선합니다.
패턴 기반 민감정보 검사는 보조 장치이며 모든 형태의 개인정보를 자동 식별한다고 보장하지 않습니다.

## 7. CLI 및 재분석

    .venv/bin/python -m mpush_analyzer.cli analysis_<32자리 소문자 16진수 ID>
    .venv/bin/python -m mpush_analyzer.cli analysis_<32자리 소문자 16진수 ID> --stage2-only

기본 CLI는 원본 해시를 검사해 재파싱한 후 이상 탐지·사례 매칭을 수행합니다.
UI의 '보고서·관리' 재분석 기능을 이용하면 보고서도 함께 갱신합니다.

## 8. 시험 방법과 한계

    .venv/bin/python -m pytest -q
    .venv/bin/python -m scripts.benchmark_synthetic --megabytes 10

벤치마크는 개인정보가 없는 가상 헬스체크 로그만 생성해 사용합니다.
임시 테스트 자료는 종료 후 삭제됩니다.

- 미지원 로그 형식은 분석 한계로 표시합니다.
- 대량 이벤트에서 일부 통계는 표본 상한을 적용하고 제한을 명시합니다.
- 원본 로그 완전성·수집 시각·기준 날짜가 불분명하면 관련 판단을 보류합니다.
- Thread Dump, 실시간 고객사 DB/OS 조회 등은 별도 확장 대상입니다.
- 실제 고객사 로그 검증은 승인된 로컬 처리 범위에서 수행해야 합니다.

## 9. 이상 징후 상세 표와 AI 자료 내보내기

- 이상 목록에서 행을 선택해 탐지 이유, 정상 대비 값, 관측 근거시각, 신뢰 정도를 확인합니다.
- 대표 시각은 보관된 근거 이벤트의 시각이며, 실제 장애 시작시각과 다를 수 있습니다.
- 로그 데이터 수집시각은 사용자가 입력한 수집 메타데이터이며, 마지막 기록부터의 공백이 장애를 의미하지 않습니다.
- 파일명은 안전한 내부 저장명과 file_XX ID로 표시합니다. 원본 업로드 이름은 보관하지 않습니다.
- 보관된 일부 근거 이벤트로부터 전체 장애 지속시간을 임의로 확정하지 않습니다.
- 선택한 징후의 Markdown/JSON과 전체 AI 분석 자료는 별개로 제공합니다.
- AI 분석 자료는 구조화 이벤트의 허용된 숫자, 종류, 시각 및 주변 이벤트만 포함하며 실제 원본 SQL·메시지·전화번호는 제공하지 않습니다.
- AI에 전달하기 전 사내 정보보호 규정에 따라 마지막으로 직접 검토해 주세요.

## 10. Windows 사용 시 주의

- Python 3.13(64-bit)을 설치한 뒤 프로젝트의 `scripts\run_windows.bat`로 실행할 수 있습니다.
- Windows에서는 POSIX의 `os.fchmod`를 호출하지 않고 파일 시스템 기본 권한을 이용합니다. 보안 경계는 NTFS ACL로 관리해야 합니다.
- 특히 매핑된 NAS 공유 드라이브에서 venv 생성·패키지 설치가 느리거나 파이썬 경로 경고가 발생할 수 있습니다. 우선 로컬 NTFS 디스크로 프로젝트를 복사하고 실행하는 것을 권장합니다.
- 고객사 로그 원본은 로컬 비공개 폴더에서만 취급하고 계정별 공유 권한을 반드시 확인합니다.
