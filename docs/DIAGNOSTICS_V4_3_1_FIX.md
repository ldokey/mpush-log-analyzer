# V4.3.1 입력 보정 — 로그가 있는데 값이 비는 경우

이 문서는 V4.3 개발 브랜치의 입력·조회 오류 수정 사항입니다. 공식 v4.2.0 릴리스 또는 사용자 Windows 설치를 자동 갱신하지 않습니다.

## 확인된 누락 경로

| 원인 | 이전 동작 | 수정 |
|---|---|---|
| 시각이 붙은 Job 헤더 | `HH:mm:ss[SSS] ## JOB 작업`을 Job 시작으로 인식하지 못함 | 기존 분리형과 시각 접두어형 모두 처리 |
| 날짜가 없는 시각-only 로그 | 조회 시작일을 입력해도 `occurred_at` 없는 이벤트는 제외됨 | 실제 기준 날짜 확인 후 임시 재해석 제공; 조회 범위와 날짜 부여를 분리 |
| 구버전 저장 분석 | 코드가 바뀌어도 기존 빈 events.jsonl을 계속 사용 | 판독기 revision 안내와 명시적인 원본 재해석 버튼 |
| 날짜가 있는 메시지 전용 로그 | 정규화 이벤트 0건이면 기본 조회 구간도 비어 있음 | 파일별 날짜·시각 단서도 기본 구간에 반영 |
| 원본 후반의 메시지 기록 | 마지막 정규화 이벤트 뒤의 메시지가 기본 구간에서 빠질 수 있음 | 원본 파일 시각 범위와 인식 이벤트 범위를 함께 사용 |
| 시간별/분별 파일명 | 연월일 뒤에 시·분이 붙으면 날짜를 놓침 | 일/시간/분 단위 회전 파일명 검증; 긴 숫자 ID 임의 절단 금지 |
| 인코딩 판정 | 첫 샘플의 문자 경계 또는 긴 ASCII 서두 때문에 한글 인코딩 오판 가능 | 전체 바이트를 작은 청크로 검증; UTF-8/BOM/CP949 처리 |
| 이전 필터 잔존 | 변경된 구간에 없는 Job·메시지 상태/가명이 필터로 남음 | 자료/구간 변경 또는 선택 값 소멸 시 필터 초기화 |
| 유사 누락 | ABNORMAL 건너뜀 무시, 쉼표 건수·지수 시간 값 오해석 | RUNNING과 별도 표시, 숫자 전체 토큰·상한 검증 |

## 수정본에서 사용하는 순서

1. 분석 대시보드에서 **실행·발송·성능**을 선택합니다.
2. **자료 인식 상태 · 원본 재해석**에서 파일 수, 줄 수, Job 수, 날짜 없는 이벤트 수, 인코딩, 실제 인식 구간을 확인합니다.
3. 이전 분석이거나 Job이 빠졌다면 **원본 재해석 (기존 분석 보존)**을 누릅니다.
4. 파일명/등록 설정에 날짜가 없다면 **날짜 없는 로그의 기준 날짜**에 실제 로그 날짜를 선택하고 확인 체크 후 재해석합니다. 오늘 날짜를 추측해서 넣지 마세요.
5. 조회 구간이 잘못됐으면 **로그 범위로 맞추기**를 누릅니다. 자료가 31일을 넘으면 최근 31일을 기본 표시하고 제한을 안내합니다.
6. 메시지 결과는 해당 탭의 원본 조회 조건에서 조회 동의 후 실행합니다. 메시지 식별값이 같은 레코드에 없거나 결과 근거가 없으면 연결/성공을 만들지 않습니다.

**조회 시작일 입력은 로그 기준 날짜를 설정하는 작업이 아닙니다.** 파일이 존재하는지, 이벤트가 인식됐는지, 이벤트에 날짜가 있는지, 현재 구간에 속하는지를 각각 구분합니다.

## 보존과 한계

재해석은 SHA-256으로 확인한 원본을 읽고 현재 브라우저 세션용 비식별 이벤트를 임시 폴더에 만듭니다. 기존 raw/manifest/events.jsonl, 문의·해결 사례, 내보내기 파일은 수정하지 않습니다. 보정한 인코딩은 같은 세션의 마스킹 근거 조회에도 적용됩니다.

임시 재해석 결과는 **실행·발송·성능 화면에만 적용**됩니다. 세션 종료/분석 변경 시 보존되지 않으며, 필요한 결과는 비식별 JSON으로 저장합니다. 다른 기존 대시보드·보고서까지 영구 갱신하려면 올바른 날짜/유형으로 자료를 새로 가져오거나 기존 명시적 재분석 기능을 사용해야 합니다. 이미 저장된 기준 날짜를 임의로 덮어쓰지 않습니다.

작업량이 없는 것과 자료 부족은 다릅니다. Job 원본이 없는 경우, 결과 조회 전, 식별값 부족, 날짜 없음, 구간 밖, 검색 조건 제외를 구분해 표시합니다. 누락된 자료를 성공 0건·실패 0건·Agent 종료로 확정하지 않습니다.

이 수정은 기존 로그 문법/입력의 신뢰성 보강이며 HA/다중 Agent·설정 연계·버전별 호환성 확대를 새로 구현한 것이 아닙니다. Windows 네이티브와 현재 사용자가 겪은 정확한 파일/설치 환경은 별도 확인이 필요합니다.
